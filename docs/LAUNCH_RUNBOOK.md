## القاعدة السارية (قرار المالك)

| الحالة | ما يُخزَّن | ما يُعرض |
|---|---|---|
| كتاب 2026 فما بعد | `2433` — مجرّد | `2433` |
| كتاب 2025 أو أقدم | `20250825` — موسوم بسنة سجلّه | `825` ووسم `2025` منفصل |
| صادر خارجي | رقم مكتب السيد المدير العام كما هو | كما هو |
| بلا رقم | حقل فارغ | «بلا رقم» |
| كتاب تدريب | `T131` | `T131` — يُحذف عند التدشين |

**سلسلةٌ واحدة لا نهائية لكل سجلّ، بلا تصفير سنوي.** أساسها أرقام 2026 كما هي
مثبَّتة في الختم: بعد 2432 يأتي 2433 — في 2027 و2028 وما بعدها. **لا بادئة سجلّ
في الرقم إطلاقاً**؛ النوع يحمله عمود `kind`، والتفرّد على `(kind, our_number)`.

القاعدة كلّها في `core/numbering.py` — **المصدر الوحيد**. من يحتاج تحليل رقم أو
توليده أو عرضه أو البحث به يستدعي الوحدة ولا يُعيد كتابة القاعدة.

## عتادُ النموذج — ما لا ينتقل بـgit

**تغيّر هذا في 2026-09-01**: صار المستودعُ **خاصّاً**، وعتادُ التشغيل يُشحَن
معه — الأوزانُ عبر **Git LFS** والبصماتُ النصّيّةُ في git عاديّ. فالاستنساخُ
يعطي نسخةً عاملة، لا نسخةً عمياءَ تبدو سليمة.

القاعدةُ العامّة تبقى «`var/` خارج git»؛ المستثنى **ما يفحصه عقدُ العتاد**
(`core/extraction/artifacts.py`) وحدَه. وما زال خارجاً عمداً: النماذجُ الميّتة
(`*_rollback`/`*_backup`)، ومخرجاتُ التدريب، و**`.encryption_key`** — سرٌّ
يُنسَخ يدويّاً ولا يدخل مستودعاً أبداً.

| الملفّ | الأثرُ عند الغياب |
|---|---|
| `var/models/number_detector.onnx` | لا صندوقَ عددٍ ولا تاريخ ⟵ المسارُ البصريُّ كلُّه صامت |
| `var/models/handwritten_digits_crnn.onnx` | لا قراءةَ عددٍ يدويّ |
| `var/models/handwritten_dates_crnn.onnx` | لا اقتراحَ تاريخ |
| `var/models/handwritten_dates_charset.json` | **أخطرُها**: النموذجُ يعمل والطقمُ ناقصٌ «/» ⟵ فكُّ الترميز يرفع `IndexError` فيسقط الاقتراحُ صامتاً |
| `var/entity_*.json` · `var/handwriting_layout_priors.json` | ترجيحُ نوع الوثيقة ومطابقةُ الجهة يضعفان |
| `.encryption_key` | يُسَكُّ مفتاحٌ جديدٌ بلا صوت ⟵ كلماتُ مرور البريد المخزّنة لا تُفكّ |

وثلاثةٌ خارج المستودع لا تقلّ لزوماً: **حزمة `onnxruntime`** (كانت غائبةً عن
`requirements.txt` حتّى 2026-09-01 — أيُّ نسخةٍ مبنيّةٍ قبلها بلا قراءةٍ يدويّةٍ
إطلاقاً)، ومحرّك **tesseract**، وبياناتُ لغته (`ara`+`eng`).

```powershell
# على نسخةٍ جديدة: اسحب الأوزان (LFS) ثمّ انسخ المفتاح ثمّ تحقّق
git lfs install
git lfs pull
copy \<مسار-آمن>\.encryption_key .          # لا يأتي مع المستودع عمداً
python manage.py models_healthcheck --strict --load --hash
```

> إن نُسي `git lfs pull` فالملفّاتُ موجودةٌ بأسمائها لكنّها **مؤشّراتٌ نصّيّةٌ
> من ثلاثة أسطر** — والفحصُ يمسكها: `--load` يفشل بفتح ONNX، وبلا `--load`
> يمسكها فحصُ الحجم (بضعةُ بايتاتٍ لا ميغابايتات).

**المساراتُ مثبَّتةٌ على جذر المشروع** منذ 2026-09-01 (`core/extraction/artifacts.py`)
فلا يعود يهمّ من أين تُقلَع الخدمة؛ وقبل ذلك كانت ستّةٌ منها نسبيّةً لمجلّد العمل
وكان الإقلاعُ من مجلّدٍ آخر **يُسقط الاستخراجَ كلَّه** لا القراءةَ اليدويّة وحدها.

## يوم التدشين — بالترتيب

> صدّر `PYTHONIOENCODING=utf-8` أوّلاً، واقرأ كلمة السرّ من `.env`
> (`LEGACY_SQL_PASSWORD`) — لا تكتبها في سطر الأوامر.

### ١. نسخة احتياطية قبل أي شيء
```powershell
& "C:\Program Files\PostgreSQL\16\bin\pg_dump.exe" -U lettersys_user -d lettersys `
  -Fc -f "D:\lettersys_data\backups\pre_launch_$(Get-Date -f yyyyMMdd_HHmmss).dump"
```

### ٢. الدمج الأخير من قاعدة المصدر
استعِد `.bak` المُحدَّث ثم شغّل معالج الاستعادة من الواجهة
(`/books/data-restore/`) أو الأمر مباشرةً. الهوية `source_ref` تمنع الازدواج،
وملفّ الحدّ يفصل الصفوف الجديدة فعلاً عن القديمة.

**تخطَّ الصفوف الفارغة**: 17 صفّاً في `IIMAIL_2025` سجّلها موظّف 2025 حجزاً ثمّ
تركها (`SUB='اااا'`، `NUM='0'`، بلا مرفق)، وهي سبب 17 من 19 رقماً مكرَّراً.
معرّفاتها في المصدر: `2133, 2134, 2127, 2128, 2137, 2138, 2139, 2132, 2830,
3498, 3500, 4039, 4284, 4415, 4420, 4421, 4422`.

**الرقمان المكرَّران الباقيان حقيقيّان** (825 و4394): الورق نفسه يحمل ختمين
بالرقم ذاته — خطأ موظّف 2025. تُركا كما هما عمداً؛ اختراع رقمٍ مميِّز يخلق رقماً
لا يوجد على أي ورقة. والقيد يستثني الصفوف المنقولة من الورق فلا يمنعها.

### ٣. إعادة بناء أرقام الوافد الجديد
```powershell
python manage.py rebase_book_numbers --database ARCHMDOC              # معاينة
python manage.py rebase_book_numbers --database ARCHMDOC --yes        # تنفيذ
```
الأمر عديم الأثر عند التكرار (مُتحقَّق: تشغيلٌ ثانٍ = 0 تغيير)، ويضبط العدّادات
على أعلى رقمٍ في السلسلة الجارية + 1.

### ٤. حذف كتب فترة التدريب
```powershell
python manage.py purge_dev_seed_books            # معاينة
python manage.py purge_dev_seed_books --yes      # تنفيذ
```
المُميِّز هو الوسم `is_training` الذي وضعه الأمر السابق — لا استنتاجٌ من
`legacy_number`. الشرط القديم كان يُفلت 73 كتاب تدريب ويلتقط 55 كتاباً حقيقياً.
القيمة التدريبية محفوظة: `LetterheadMemory` و`DataExtractionResult` و`OCRResult`
تُفصَل ولا تُمحى.

### ٥. التحقّق النهائي
```powershell
# العتادُ أوّلاً: مجموعةُ الاختبار تخضرّ على جهازٍ بلا أوزانٍ إطلاقاً،
# فلا تصلح بوّابةً لهذا الصنف من العطب.
python manage.py models_healthcheck --strict --load
python manage.py test --settings=lettersys.settings_test
```
ثم بالعين على الواجهة: افتح قائمة الكتب وتأكّد أنّ الرقم يُعرض مجرّداً، وأنّ
وسم السنة يظهر لكتب 2025 وما قبلها وحدها، وأنّ التبويبات تُظهر الرقم التالي
الصحيح لكل سجلّ.
