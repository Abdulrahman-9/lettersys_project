# وثيقة تصميم — وكيل المسح العام (TWAIN/WIA) لـ LetterSys

**التاريخ:** 2026-06-24 · **القرار المرجعي:** قرار المالك #1 (وكيل TWAIN/WIA كامل مستقل عن المُصنّع) · **الحالة:** مسودّة للمراجعة قبل التنفيذ

> هذه وثيقة تصميم فقط — لا كود إنتاجي بعد. بعد موافقتك أنفّذ المرحلة 1.

---

## 1. الخلفية والمشكلة

التدفّق الحالي مربوط بـ **Canon CaptureOnTouch حصراً** وهشّ ببنيته:

- الزر في الواجهة يطلب `POST /books/api/scan/launch/` فيُعيد رابط بروتوكول `lettersys-scan://...` ([core/views/scan_settings.py](core/views/scan_settings.py#L685)).
- المتصفح يُطلق البروتوكول عبر iframe → ويندوز يشغّل [scan_manager/scan_manager.py](scan_manager/scan_manager.py) → يُشغّل CaptureOnTouch.exe.
- CaptureOnTouch يحفظ ملفاً في مجلد المراقبة → المراقب في [core/apps.py](core/apps.py) يلتقطه → OCR → token.
- الواجهة تستطلع `watcher-status` لاكتشاف الملف.

**العيوب الجوهرية:**
1. **مُصنّع واحد**: لا يعمل مع Fujitsu/HP/Epson/Brother أو أي ماسح شبكي/ADF.
2. **بروتوكول fire-and-forget**: `lettersys-scan://` لا يُعيد قيمة للصفحة — لذا الاعتماد على مجلد المراقبة كقناة غير مباشرة (مصدر هشاشة + تبويبات متكررة + سباقات).
3. **سلسلة من 4 عمليات** يجب أن تعمل معاً بلا إشارة عند تعطّل إحداها.
4. **لا ADF/متعدد صفحات/duplex حقيقي**؛ و`Scan-Book.ps1` (WIA) يحفظ JPG صفحة واحدة فقط.
5. **لا اختيار جهاز** ولا ضبط (DPI/ملون/مصدر).

**القيد الفيزيائي الحاكم:** المتصفح **لا يستطيع** الوصول لأجهزة المسح مباشرةً (لا توجد TWAIN/WIA في JavaScript). أي حل عام يتطلب **وكيلاً محلياً أصلياً** يجسر بين المتصفح والماسح.

---

## 2. الأهداف / غير الأهداف

**الأهداف:**
- دعم **أي ماسح** عبر TWAIN و/أو WIA (flatbed + ADF + duplex + متعدد صفحات).
- إخراج **PDF** أصلاً (متعدد الصفحات).
- **اختيار الجهاز** من قائمة أجهزة النظام + ضبط (مصدر/DPI/لون).
- **قناة إرجاع مباشرة** للصفحة (لا اعتماد على مجلد كوسيط) → يلغي التبويبات/السباقات.
- مؤشّر **جاهزية حيّ** (هل الوكيل يعمل؟ هل يوجد ماسح؟).
- **توافق رجعي**: إبقاء مسار مراقبة المجلد عاملاً لأي ماسح/MFP شبكي.

**غير الأهداف (هذه المرحلة):**
- وضع الدفعة Batch (مؤجّل — قرار #4).
- دعم macOS/Linux (Windows أولاً؛ التصميم يسمح بالتوسّع).
- استبدال محرّك OCR (منفصل — قرار #3).

## 3. مقارنة الخيارات التقنية للمسح من الوكيل

| الخيار | يدعم | مزايا | عيوب | التبعية |
|--------|------|-------|------|---------|
| **WIA عبر pywin32 (COM)** | معظم ماسحات ويندوز، flatbed + ADF (محدود) | مدمج في ويندوز، لا تثبيت سواقات إضافية | ADF/duplex متفاوت، لا PDF أصلاً (نجمّع صور→PDF)، COM معقّد | `pywin32` (غير مثبّت) |
| **TWAIN عبر pytwain** | المعيار الصناعي، ADF/duplex ممتاز، حوار الماسح | أقوى تحكّم ودعم ADF | تعقيد 32/64بت، DSM، نوافذ حوارية | `pytwain` (غير مثبّت) |
| **NAPS2 Console (CLI)** ⭐ | **WIA + TWAIN + ESCL/SANE**، ADF، duplex، **PDF أصلاً**، OCR اختياري | مجاني مفتوح المصدر، يغطّي كل شيء بأمر واحد، يتولّى تعقيد TWAIN/WIA نيابةً عنا | تبعية خارجية (تثبيت NAPS2) | تثبيت NAPS2 (غير مثبّت) |
| Dynamsoft / Scanner.js | TWAIN/WIA/SANE في المتصفح | جاهز، احترافي | **تجاري مدفوع** | ترخيص |

**التوصية:** اعتماد **NAPS2 Console** كمحرّك مسح أساسي داخل الوكيل (يحلّ TWAIN+WIA+ADF+duplex+PDF بأمر واحد ومستقر)، مع **WIA عبر pywin32 كمسار احتياطي** بسيط (flatbed صفحة واحدة) إن لم يُثبَّت NAPS2. هذا يتجنّب إعادة اختراع تعامل TWAIN/WIA المعقّد، ويعطي عمومية حقيقية بأقل مخاطرة.

> `Pillow + PyMuPDF` متاحان أصلاً في المشروع — كافيان لتجميع صور WIA إلى PDF في المسار الاحتياطي.

## 4. المعمارية المقترحة

```
┌─────────────────────────┐         ┌──────────────────────────────┐
│  المتصفح (شاشة المسح)   │         │  الوكيل المحلي (LetterSys      │
│  extraction_smart.js    │  HTTP   │  Scan Agent) — عملية مقيمة    │
│                         │ ───────▶│  127.0.0.1:17865 فقط          │
│  GET  /agent/health     │◀─────── │                              │
│  GET  /agent/devices    │  JSON   │  • يعدّ الأجهزة (WIA/TWAIN)    │
│  POST /agent/scan       │         │  • يمسح عبر NAPS2 Console      │
│       {device,source,   │         │  • يُخرج PDF متعدد الصفحات     │
│        dpi,duplex}      │         │  • يُعيد الملف للصفحة مباشرةً  │
└───────────┬─────────────┘         └───────────────┬──────────────┘
            │ (الـ PDF الناتج)                        │ يحفظ نسخة في
            ▼                                         ▼ مجلد المراقبة (توافق)
┌─────────────────────────────────────────────────────────────────┐
│  Django: نفس خط الاستيعاب الحالي (run_ocr_isolated → token)        │
│  إمّا رفع مباشر POST /scan/process، أو إسقاط في watch_folder       │
└─────────────────────────────────────────────────────────────────┘
```

**المكوّن الجديد: «وكيل المسح المحلي»** — خدمة Python صغيرة مقيمة على جهاز المستخدم:
- تستمع على `127.0.0.1` فقط على منفذ ثابت (مثلاً 17865) — لا تُعرَّض للشبكة.
- تُشغَّل تلقائياً مع ويندوز (Startup/Task Scheduler)، أو يدوياً، أو عبر البروتوكول الحالي كـ bootstrap.
- تُغلَّف لاحقاً كـ `.exe` عبر PyInstaller لتثبيت سهل بلا Python (المرحلة 3).

**لماذا وكيل HTTP بدل البروتوكول الحالي؟** البروتوكول `lettersys-scan://` لا يُرجع نتيجة للصفحة. وكيل HTTP يُعيد الـPDF/المسار مباشرةً في استجابة `POST /scan` → الصفحة تعرف فوراً متى وأين اكتمل المسح → **يلغي مجلد-الوسيط والتبويبات والسباقات**.

## 5. بروتوكول الاتصال (Agent API)

كل النقاط على `http://127.0.0.1:17865` وتتطلّب رأس `X-LetterSys-Token` (انظر الأمن):

| النقطة | الطريقة | الوصف | الاستجابة |
|--------|---------|-------|-----------|
| `/agent/health` | GET | فحص حياة الوكيل + إصدار + توفّر NAPS2 | `{ok, version, backend:"naps2"|"wia", scanners_count}` |
| `/agent/devices` | GET | تعداد الماسحات المتصلة | `{devices:[{id,name,driver:"twain"|"wia"}]}` |
| `/agent/scan` | POST | مسح فعلي | `{ok, pdf_base64|file_path, pages}` أو `{ok:false, error}` |

`POST /agent/scan` body: `{device_id, source:"flatbed"|"adf", duplex:bool, dpi:200, color:"color"|"gray", format:"pdf"}`.

تدفّق الإرجاع — خياران (يُحسمان في المرحلة 1):
- **(أ) رفع مباشر:** الوكيل يُعيد الـPDF (base64 أو stream) → الصفحة تُرسله `POST /books/api/scan/process-upload/` → Django يحفظه ويشغّل OCR ويُعيد token. **الأنظف — لا مجلد وسيط.**
- **(ب) إسقاط في المجلد:** الوكيل يحفظ في `watch_folder` → المراقب يلتقط (توافق مع الموجود). يُبقى كـ fallback للماسحات الشبكية.

---

## 6. تدفّق المستخدم الجديد

1. فتح شاشة المسح → JS يستدعي `/agent/health`:
   - الوكيل يعمل + يوجد ماسح → مؤشّر **أخضر «جاهز»** + قائمة الأجهزة.
   - الوكيل متوقّف → بانر **«شغّل وكيل المسح»** برابط تنزيل/تشغيل (بدل المودال المقتحم الحالي).
2. المستخدم يختار الماسح + المصدر (ADF/flatbed) مرة، يُحفظ كتفضيل.
3. ضغط **«مسح»** → `POST /agent/scan` → شريط تقدّم حقيقي (الوكيل يبثّ الحالة).
4. عند الاكتمال: الـPDF يصل للصفحة → فتح فوري للمعاينة + بدء OCR في الخلفية → ملء الحقول.
5. لا تبويبات تُفتح، لا انتظار مجلد، لا «3 عمليات خفية».

## 7. التكامل مع الكود الحالي

**يُستبدَل:**
- `scan_manager/scan_manager.py` (مُشغّل CaptureOnTouch) → منطق المسح ينتقل للوكيل العام.
- `scan_launch_api` يتحوّل من «إرجاع رابط بروتوكول» إلى «وسيط/تحقّق» اختياري.

**يبقى (إعادة استخدام):**
- خط الاستيعاب: `run_ocr_isolated` + `scan_token` cache + `scan_file_serve` ([scan_settings.py](core/views/scan_settings.py#L508)) — بلا تغيير.
- مجلد المراقبة + المراقب (مالك وحيد عبر `SCAN_WATCHER_MODE` الذي أضفناه) — كمسار fallback للماسحات الشبكية/MFP.
- صفحة الإعدادات: تُحدَّث لعرض حالة الوكيل + قائمة الأجهزة بدل مسارات CaptureOnTouch.

**نقطة Django جديدة:** `POST /books/api/scan/process-upload/` تستقبل PDF من الوكيل، تحفظه، تشغّل OCR، تُعيد token (تشبه `scan_process_local_file` الموجود لكن برفع مباشر).

## 8. الأمن

- الوكيل يستمع على `127.0.0.1` فقط (لا `0.0.0.0`) — لا وصول من الشبكة.
- **token مشترك**: Django يولّد token جلسة، يمرّره للصفحة، والصفحة ترسله للوكيل في `X-LetterSys-Token`؛ الوكيل يرفض الطلبات بلا token صحيح → يمنع مواقع/تطبيقات محلية أخرى من تشغيل ماسحك (مكافحة DNS-rebinding/CSRF محلي).
- CORS: الوكيل يسمح فقط لأصل `http://127.0.0.1:8000` (و`localhost`).
- حدود الحجم/الصفحات + مهلة لكل عملية مسح.

## 9. خطة التنفيذ المرحلية

| المرحلة | المحتوى | المخرَج |
|---------|---------|---------|
| **0 — تثبّت (spike)** | تثبيت NAPS2 + تجربة `NAPS2.Console -o out.pdf --driver wia/twain --source adf` على ماسحك الفعلي | تأكيد أن NAPS2 يرى ماسحك ويُخرج PDF |
| **1 — MVP** | وكيل محلي (http.server/Flask) + `/health` + `/devices` + `/scan` (flatbed، NAPS2 backend) + رفع مباشر لـ Django + استبدال الزر | مسح صفحة واحدة من أي ماسح عبر الوكيل |
| **2 — ADF/متعدد** | ADF + duplex + متعدد صفحات + اختيار جهاز/مصدر/DPI في الواجهة + مؤشّر جاهزية | مسح كومة → PDF متعدد الصفحات |
| **3 — تغليف** | PyInstaller → `.exe`، تشغيل تلقائي مع ويندوز، مثبّت موقّع، بثّ تقدّم (SSE/WebSocket) | تثبيت بنقرة، تجربة سلسة |
| **4 — تنظيف** | تقاعد مسار Canon الحصري، WIA fallback، توثيق | إزالة الدين |

> وضع الدفعة (قرار #4) يُبنى فوق المرحلتين 2 و3 لاحقاً.

## 10. التبعيات الجديدة المطلوبة

- **NAPS2** (تثبيت على جهاز المستخدم — مجاني): محرّك المسح العام.
- `pywin32` (اختياري — مسار WIA الاحتياطي وتعداد الأجهزة).
- لا تبعيات بايثون ثقيلة جديدة على جانب Django (الرفع عبر نقطة موجودة الطراز).

## 11. المخاطر والأسئلة المفتوحة

| المخاطرة | التخفيف |
|----------|---------|
| تفاوت سواقات الماسحات (TWAIN 32/64بت) | NAPS2 يتولّى ذلك؛ نوثّق الماسحات المُختبَرة |
| تثبيت NAPS2 على كل محطة | مثبّت مُجمَّع/سكربت؛ أو تغليف NAPS2 محمول مع الوكيل |
| تشغيل الوكيل تلقائياً وبقاؤه حيّاً | Task Scheduler/Startup + مؤشّر صحّة يطلب تشغيله إن توقّف |
| توقيع الـ.exe (تحذيرات SmartScreen) | شهادة توقيع كود (قرار لاحق) |
| **سؤال للمالك:** هل ماسحك الحالي TWAIN أم WIA أم شبكي؟ وما طرازه؟ | يحدّد أولوية الاختبار في المرحلة 0 |
| **سؤال:** رفع مباشر (أ) أم إبقاء مجلد المراقبة (ب) كقناة أساسية؟ | يحدّد بنية المرحلة 1 |

## 12. الخلاصة

الحل الجذري لـ«المسح لا يعجبني وفيه أخطاء» هو **استبدال سلسلة Canon الهشّة بوكيل محلي عام** يجسر المتصفح بالماسح عبر NAPS2 (WIA+TWAIN+ADF+PDF)، ويُعيد الـPDF مباشرةً للصفحة. هذا يحقّق قرارك #1، ويُزيل التبويبات/السباقات/الحصر بمُصنّع، ويُبقي خط OCR الحالي كما هو.

**التالي:** موافقتك على الوثيقة + الإجابة على السؤالين أعلاه → أبدأ المرحلة 0 (spike على NAPS2 بماسحك) ثم المرحلة 1 (MVP).
