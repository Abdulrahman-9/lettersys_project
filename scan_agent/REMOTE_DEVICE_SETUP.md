# إعداد الجهاز الثاني (الذي يحتوي على الماسح)

## 1) جهّز رمزاً مشتركاً بين الجهازين
وكيل المسح والتطبيق يجب أن يستخدما الرمز نفسه، وإلا سيرفض الوكيل طلبات المسح.

على جهاز التطبيق (A)، شغّل الوكيل مرة واحدة محلياً كي ينشئ الرمز إن لم يكن موجوداً:

```powershell
py -3 -m scan_agent
```

أوقفه بـ `Ctrl+C`، ثم انسخ الملف `%LOCALAPPDATA%\LetterSys\agent_token.txt` من الجهاز A إلى المسار نفسه على الجهاز B. تعامل مع الملف كسِرّ، ولا ترسله علناً.

## 2) انسخ مجلد الوكيل
يجب أن يكون على الجهاز الثاني:
- مجلد `scan_agent` كاملاً
- Python 3.11 أو 3.12 مثبت؛ NAPS2 وحده لا يكفي لتشغيل وكيل Python.

## 3) اضغط مرتين على ملف التشغيل
من مجلد المشروع، شغّل:

- `scan_agent\remote_start.bat`

أو في PowerShell:

```powershell
$env:LETTERSYS_AGENT_HOST = '0.0.0.0'
$env:LETTERSYS_AGENT_PORT = '17865'
$env:LETTERSYS_AGENT_ALLOWED_ORIGINS = 'http://172.16.2.16:8000'
py -3 -m scan_agent
```

## 4) إذا لم يعمل `py` أو `python`
ثبت Python 3.11 أو 3.12 من Microsoft Store أو python.org.

ثم أعد التشغيل.

## 5) عنوان التطبيق
تأكد أن IP في `LETTERSYS_AGENT_ALLOWED_ORIGINS` هو IP الجهاز الذي يستضيف التطبيق، مثل:

```text
http://172.16.2.16:8000
```

## 6) تحقق من أن الوكيل يعمل
افتح المتصفح على الجهاز الثاني وادخل:

```text
http://127.0.0.1:17865/agent/health
```

يجب أن تعطي JSON يشير إلى أن NAPS2 موجود.

## 7) إذا كانت الاستجابة لا تعمل
- تأكد أن NAPS2 مثبت
- تأكد أن الماسح متصل ومشغل
- اسمح باتصالات TCP الواردة على المنفذ 17865 في جدار حماية Windows على الجهاز B.
- تأكد أن `LETTERSYS_AGENT_HOST=0.0.0.0`

## 8) إعداد التطبيق الرئيسي
على الجهاز الذي يشغّل التطبيق، اضبط:

```powershell
$env:LETTERSYS_AGENT_URL = 'http://172.16.2.18:17865'
```

ثم أعد تشغيل تطبيق Django من نافذة PowerShell نفسها كي يرث المتغير، وافتح التطبيق في المتصفح.

## ملاحظة
هذا الوكيل يستند إلى NAPS2 ويستخدم ماسح الجهاز B. يتطلب تثبيت Python وNAPS2 ونسخ مجلد `scan_agent` وملف الرمز المشترك. لا تشارك ملف الرمز خارج الأجهزة الموثوقة.
